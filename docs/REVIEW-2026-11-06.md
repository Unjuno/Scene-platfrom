## 1. 改善の優先順位

| 優先度 | 問題 | 改善 | 成功条件 |
|---|---|---|---|
| P0 | SitesのソースがGitHubにない | 稼働コードとデータ保存スキーマを安全に同期し、PR＋プレビュー環境で変更 | 同じコードから再現可能なプレビューが立つ |
| P0 | 非同期処理と「成功」の境界が曖昧 | 明示的状態機械と副作用分離、DBコミット後だけ成功表示 | 保存中の再操作・タイムアウト・競合でデータが失われない |
| P0 | 投稿・アフレコ・星評価が匿名表示から実証できない | A/B/C別アカウントE2E、権限、バージョン参照、重複防止 | 保存→公開→第三者視聴→音声版→独立星評価が再現可能 |
| P0 | アフレコ許可のサーバー境界が不明 | owner/workVersion/permissionの各チェックを最終公開トランザクションで再評価 | OFF/別ユーザー/古いrevisionを拒否する |
| P1 | ゲーム風の雰囲気に対し操作意図が分かりにくい | ロビー／シアター／制作室／収録室の目的を整理し、ボタンを具体的動詞に | 初見の利用者が主要フローを独力で進められる |

## 2. 改善したナビゲーション構造

1. **ロビー** — おすすめ作品を即座に鑑賞する入口。空ランキングを主役にしない。
2. **物語を観る** — 検索・絞り込みと作品カード。公開版とローカル下書きは区別する。
3. **物語をつくる** — 画像追加、順序、1枚に複数台詞、アフレコ許可、プレビュー、下書き保存。
4. **声で参加する** — 許可ONの作品を発見し、収録準備へ進む。
5. **自分の作品** — 保存した下書きと出演履歴。本番ではサインイン状態に従う。

**初回閲覧は認証不要、公開や星評価は認証必須。** 録音練習は匿名でも可能という元仕様を維持。作品は無音でも完成でき、台本は視聴中に画像上へ重ねない。

## 3. 新しい責務分担

| 層 | 内容 | 制約 |
|---|---|---|
| Presentation | semantic HTML/CSS、装飾Canvas、モバイルNav、フォーカス管理 | 操作をCanvasに閉じ込めない |
| View State | ナビゲーション、読み込み・空・失敗状態、選択作品・選択コマ | ドメインの権限判定をしない |
| Actors | auth/work/editor/player/recorder/upload/dub/ratingの独立した状態機械 | 遷移は純粋、外部副作用を直接実行しない |
| Domain | 不変のWorkRevision、Scene/Cue、Dub、Take、Rating、Permission | 作品・声のデータ境界を維持 |
| Adapters | Sites認証、メタデータ、メディア保存、評価、公開API | 可用性を検証してから実装する |
| Infrastructure | DB、Blob、アクセス制御、監査ログ、バックアップ、CDN | Public GitHubと利用者データを分離 |

## 4. なぜ「状態機械」が必要か

同じ「保存」ボタンでも、未編集・編集中・検証中・保存中・保存済み・失敗時で意味が異なる。無秩序なブールフラグ（`isLoading`, `isSaving`, `isPublished`, `hasError`）の組合せは「保存中なのに公開済み」など矛盾する状態を生む。

機械ごとに一つの明示的状態を保持し、**イベント・許可条件（guard）・副作用・完了イベント**を切り分ける。ネットワーク失敗や画面遷移では古い結果を棄却し、成功表示を最終コミット確認まで遅延する。詳細は `STATE-MACHINES.md`。

## 5. 実装済み（この作業のローカル試作）

- ダークシネマティックなレスポンシブUIと装飾Canvas。狭幅時は下部ナビへ切替。
- ロビー、作品探索、無音の手動コマ送り、最後まで鑑賞した後の終了状態。
- 作者の作品フォーム、画像選択、複数台詞、シーン順序編集、プレビュー。
- ブラウザのIndexedDBへの下書き保存とローカルライブラリ。**一般公開ではない。**
- アフレコ許可作品の練習収録、音声ファイル取り込み、人/AI/混合の出自ラベル、ローカルテイク保持・試聴・ダウンロード。
- 視聴画面は字幕なし。収録画面でのみ台本を表示。
- 認証・公開・星評価・ランキングの本番APIを装った偽の完了表示は行わない。
- State machine定義と単体テスト。コードの文法チェックと単体テストは完了。
