# SCENE — ゲーム型WebデザインとUX仕様 v1

## 1. 原則

**夜の劇場 / 静止画 / ひとつの絵にいくつもの声。** 演出は鑑賞への入口として機能させ、入力の邪魔には使わない。

- **ゲームのような世界観をDOMの操作性と両立。** Canvasは背景の微細な灯りなど装飾だけ。作品画像は意味を持つ`img`で表示し、ボタン・フォーム・見出しはHTMLで提供。
- **視聴者優先の入口。** 初見でまず作品を見られ、制作と出演は同じ層の二次導線。
- **機能を偽装しない。** ランキングが空なら空と明記。ログイン・保存・公開が未接続なら具体的に示す。意味のない星数を生成しない。
- **静止画の価値。** 作品画像をクロップしない。字幕は絵に重ねない。無音版は手動で進める。
- **責務別の密度。** ロビーは空間的、シアターは没入的、制作と録音は明快なフォーム。

## 2. デザイントークン（提案）

| 用途 | 値 | 意図 |
|---|---|---|
| グローバル背景 | `#0b1219` | 深い舞台袖 |
| サーフェス | `#17242b` | パネル・作業面 |
| 主文字 | `#f2ebdb` | 生成りの読みやすさ |
| 補助文字 | `#aeb9b6` | 暗い背景上の可読性 |
| 強調・枠線 | `#d4b47d` | 金属の金、押し付けない上質感 |
| 朱色 | `#c76c56` | 破棄・注意・役割強調 |
| 状態確認 | `#5bc4a1` | ローカル処理が利用可能な状態 |
| ロビーの主CTA | 金色の塗り | 主要な一つの行動を目立たせる |

見出しは明朝系、日本語の本文・操作はゴシック系。ローカルフォントfallbackを持ち、ネットワークフォント必須にしない。

## 3. 各画面で最も重要な操作

| 画面 | 主要な一手 | 二次操作 | 終了／エラー |
|---|---|---|---|
| ロビー | 「幕を開ける」 | 「物語を探す」／「つくる」／「演じる」 | ランキング0件を小さく説明 |
| 作品一覧 | 検索・作品カード選択 | 許可作品だけ絞る | 0件なら検索語を変える案内 |
| シアター | 無音版なら「次の絵へ」 | 前の絵、任意コマ、全画面 | 最終コマで「鑑賞を終える」→評価案内 |
| 制作室 | 画像選択＋台本編集 | コマ追加・並替・プレビュー | 保存が終わるまで「保存完了」と言わない |
| 声の参加 | 対象作品を選ぶ | 許可条件を見る | 募集0件は制作室に戻す |
| 収録室 | マイク準備→録音→停止→テイク確認 | 音声読み込み・ダウンロード | 許可拒否、途中離脱、保存失敗を説明 |
| ライブラリ | 下書きを編集 | プレビュー・再訪 | 端末限定の保存を常に表示 |

## 4. レスポンシブ方針

- 701px以上は左サイドナビ。700px以下は下部タブナビへ切替（5項目）。
- 小画面で固定サイドバーを押し付けない。作品カードは1列、音声や制作フォームは縦方向へ配置。
- 読む文字は大きめ、操作対象は少なくとも44px程度を初期設計目標とする（WCAG 2.2 AAの最小対象サイズ基準そのものではない）。
- `prefers-reduced-motion`なら背景のCanvas描画を静止化し、アニメーションや滑らかスクロールを無効にする。
- キーボードにはスキップリンク、`focus-visible`、シアターの左右キーを提供。入力欄にフォーカスがあるときは左右キーでコマを動かさない。
- 再生中にCanvasテキストだけで意味を伝えない。画像には代替テキストを与える。

## 5. 検証基準

- **可読性:** WCAG 2.2 AAの通常文字は原則コントラスト比4.5:1以上、大きな文字は3:1以上。数値測定がない画面で「適合」と断定しない。
- **操作対象:** 主要なボタンは44px程度を設計目標とし、実機で誤タップを確認。
- **初見の動線:** 作品カードへ迷わず入り、無音コマ送りと終了ができること。
- **入力中の状態:** 画像処理・保存・マイク権限待ち中にも画面が何をしているか分かること。
- **実機:** PC（Chromium/Firefox）、iOS Safari、Android Chromeの現在版で確認。スクリーンショットだけで完全なWCAG適合は判断できない。

## 6. ユーザーテスト仮説（未測定）

**H（反証可能仮説）:** 初見の利用者が、ロビー→作品選択→最終コマまで、説明者なしで完了できる割合が90%以上。さらに制作画面で「画像を選ぶ」を見つけられる割合が90%以上。

**T（最小検証）:** 初見利用者を20人以上集め、PC／スマホを各10人以上に割り振り、独力で実行してもらう。イベントと画面録画（本人の同意あり）を記録。繰り返し見せず、失敗・時間切れを含む全例を数える。

**D（合否条件）:** 各導線の完了率が90%以上なら一次PASS、80%未満ならFAIL、間の値またはサンプル不足ならUNCERTAIN。統計的優越の実証ではなく、設計の初期受入判定。

**C（対立仮説）:** ゲーム的演出の視認性が高くても、初見の利用者はボタン名・場面の切替に迷う。

**U（不確かさ）:** 端末性能、実画面サイズ、ゲーム経験、ネットワーク待ち、画像素材の内容、アクセシビリティ要件。サンプル不足の場合は合格を主張せず、追加試験を設計する。
